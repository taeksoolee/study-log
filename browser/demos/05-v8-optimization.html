히든 클래스 (Hidden Classes)

V8은 JavaScript 객체에 내부적으로 히든 클래스(Hidden Class)를 부여합니다. 같은 순서로 프로퍼티를 추가하면 동일한 히든 클래스를 공유해 최적화 코드를 재사용할 수 있지만, 순서가 다르면 서로 다른 클래스 체인이 만들어져 최적화 효과가 줄어듭니다.

좋은 패턴 생성자 함수로 일관된 순서 유지
function Point(x, y) { this.x = x; // 항상 x 먼저 this.y = y; // 항상 y 다음 } const p1 = new Point(1, 2); const p2 = new Point(3, 4);
버튼을 눌러 단계별로 실행하세요.
p1과 p2는 동일한 히든 클래스(C2)를 공유합니다. V8은 최적화 코드를 한 번만 생성하고 두 객체에 재사용합니다.
나쁜 패턴 다른 순서로 프로퍼티 추가
const obj1 = {}; obj1.x = 1; // x → y 순서 obj1.y = 2; const obj2 = {}; obj2.y = 1; // y → x 순서 (다름!) obj2.x = 2;
버튼을 눌러 단계별로 실행하세요.
obj1은 C0→C1→C2, obj2는 C0→C3→C4 경로를 사용합니다. 히든 클래스가 달라 최적화 코드를 공유할 수 없어 성능이 저하됩니다.
인라인 캐싱 (Inline Caching)

V8은 함수 호출 지점마다 IC (Inline Cache)를 유지합니다. 항상 같은 타입이 오면 캐시를 최적화하고, 여러 타입이 섞이면 캐시 효율이 떨어집니다.

function getX(obj) { return obj.x; // 이 프로퍼티 접근에 IC가 생성됩니다 }
모노모픽 (Monomorphic) 항상 같은 타입 → 캐시 히트 ✓ 최적화됨
getX({ x: 1 }); // Point 타입 getX({ x: 2 }); // Point 타입 (같음!) getX({ x: 3 }); // Point 타입 (같음!)
호출
getX()
IC 캐시
Point → x
결과
obj.x
히트: 0 0
미스: 0 0
상태: 대기
폴리모픽 (Polymorphic) 2~4개 타입 혼합 → 캐시 부분 히트 ⚠ 경고
getX(new Point(1, 2)); // Point 타입 getX(new Circle(5)); // Circle 타입 getX(new Rect(3, 4)); // Rect 타입
호출
getX()
IC 캐시 (복수)
?
결과
obj.x
히트: 0
미스: 0
타입 수: 0
상태: 대기
메가모픽 (Megamorphic) 5개 이상 타입 → 최적화 포기 ✗ 최적화 포기
// 매번 다른 히든 클래스를 가진 객체가 전달됨 [A, B, C, D, E, F, ...].forEach(obj => getX(obj));
호출
getX()
IC 캐시
MEGAMORPHIC
결과 (느림)
obj.x
히트: 0
미스: 0
타입 수: 0
상태: 대기
JIT 컴파일 사이클

V8은 함수 호출 횟수에 따라 점진적으로 최적화를 적용합니다. Interpreter → Sparkplug → Maglev → Turbofan 순서로 컴파일 단계가 올라가며, 타입이 바뀌면 역최적화(Deoptimization)가 발생합니다.
