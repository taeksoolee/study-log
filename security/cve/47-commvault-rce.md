# CVE-2025-34028 - Commvault Command Center 원격 코드 실행

## 개요

| 항목 | 내용 |
|------|------|
| CVE ID | CVE-2025-34028 |
| CVSS | 10.0 (Critical) |
| 영향 소프트웨어 | Commvault Command Center |
| 영향 버전 | 11.38.0 ~ 11.38.19 |
| 수정 버전 | 11.38.20 이상 |
| 공격 유형 | Remote Code Execution (사전 인증 불필요) |
| 발견일 | 2025-04-17 |

## 영향 범위 & 심각성

### 왜 치명적인가

Commvault는 **엔터프라이즈 백업 및 복구 솔루션** 시장의 리더다. Command Center는 전체 백업 인프라를 관리하는 웹 기반 콘솔이며, 이 시스템이 장악되면:

- 모든 백업 데이터 접근/삭제 가능
- 랜섬웨어 공격 시 복구 수단 자체가 무력화
- 백업 대상 시스템(프로덕션 서버)에 대한 에이전트 제어 가능

### 실제 피해

- 2025년 4월 CISA KEV에 등재 — 실제 악용 확인
- 랜섬웨어 그룹이 백업 시스템을 우선 타겟팅하는 전략과 결합
- Commvault 고객: Fortune 500 기업 다수, 금융기관, 의료기관, 정부기관
- 백업 삭제 후 랜섬웨어 배포 → 피해 기업의 협상력 완전 제거

### 영향 규모

- Commvault는 전 세계 100,000개 이상의 조직에서 사용
- Command Center가 인터넷에 노출된 경우 즉시 공격 가능
- 내부망에서도 초기 침투 후 횡적 이동으로 도달 가능

## 취약점 기술 분석

### 근본 원인

Commvault Command Center의 웹 인터페이스에서 **SSRF(Server-Side Request Forgery)를 통한 임의 파일 업로드 및 코드 실행**이 가능하다.

### 기술적 메커니즘

1. **사전 인증 SSRF**: Command Center의 특정 API 엔드포인트가 인증 없이 접근 가능
2. **ZIP 파일 다운로드 유도**: SSRF를 통해 공격자가 제어하는 외부 서버에서 ZIP 파일 다운로드
3. **경로 순회(Path Traversal)**: ZIP 파일 내 엔트리의 경로를 조작하여 웹 루트에 파일 배치
4. **웹쉘 배치**: JSP/서블릿 형태의 웹쉘이 서버에 배치됨
5. **코드 실행**: 배치된 웹쉘을 통해 시스템 명령 실행

### 공격의 용이성

- 인증 완전 불필요 (CVSS 10.0의 핵심 이유)
- 단일 HTTP 요청으로 익스플로잇 체인 시작 가능
- 공격 복잡도 낮음 — 스크립트 키디 수준에서도 악용 가능
- 공개된 PoC 코드가 신속히 확산됨

### 관련 취약점 체이닝

SSRF → Path Traversal → 웹쉘 배치라는 3단계 체인이 하나의 HTTP 세션에서 완성되며, 각 단계가 독립적으로는 중간 심각도이지만 결합 시 CVSS 10.0이 된다.

## 공격 시나리오

### 공격 단계

```
1. 스캔: Commvault Command Center 인스턴스 발견 (기본 포트 443)
2. SSRF 트리거: 인증 없이 접근 가능한 API에 조작된 URL 전달
3. 악성 ZIP 서빙: 공격자 서버에서 경로 순회가 포함된 ZIP 파일 제공
4. 파일 배치: ZIP 추출 과정에서 웹쉘이 웹 루트에 배치됨
5. RCE: 웹쉘 접근 → 시스템 권한으로 명령 실행
6. 백업 파괴: 백업 카탈로그 삭제, 백업 에이전트를 통한 프로덕션 접근
```

### 랜섬웨어 킬체인에서의 역할

```
초기 침투 → 내부 정찰 → Commvault 발견 → CVE-2025-34028 악용
    → 백업 삭제/암호화 → 프로덕션 서버 랜섬웨어 배포
    → 피해 기업: 복구 불가 상태에서 몸값 협상
```

## 방어 방법

### 즉시 조치

1. **패치 적용**: Commvault Command Center 11.38.20 이상으로 즉시 업데이트
2. **네트워크 격리**: Command Center 웹 인터페이스를 관리 네트워크로 제한
3. **아웃바운드 제한**: Command Center 서버의 외부 인터넷 접근 차단 (SSRF 무력화)

### 장기 대책

- 백업 시스템을 별도 보안 존에 배치 (3-2-1 규칙의 '1' = 오프라인/에어갭)
- 백업 관리 콘솔의 접근을 MFA + IP 화이트리스트로 제한
- 백업 무결성 검증 자동화 (정기적 복구 테스트)
- 불변(Immutable) 백업 스토리지 도입 — 삭제/수정 불가 보존 기간 설정
- WAF 배치로 SSRF 패턴 차단

### 탐지 방법

- Command Center 서버의 비정상 아웃바운드 HTTP 요청 모니터링
- 웹 루트에 예기치 않은 파일 생성 감지 (FIM)
- 백업 카탈로그/정책 변경 알림 설정
- Command Center 접근 로그에서 비인증 API 호출 패턴 분석
- ZIP 파일 추출 이벤트와 경로 순회 패턴 탐지

## 교훈

1. **백업은 최후의 방어선**: 백업 시스템 자체의 보안이 전체 레질리언스를 결정
2. **SSRF는 과소평가되는 취약점**: 내부 시스템 접근, 파일 다운로드 등으로 체이닝되면 RCE까지 이어짐
3. **인증 없는 엔드포인트 = 최고 위험**: 관리 콘솔에 인증 없이 접근 가능한 API가 존재하면 안 됨
4. **아웃바운드 트래픽 제한**: 서버가 임의 외부 URL에 접근하지 못하면 SSRF 체인 차단 가능
5. **불변 백업의 필요성**: 백업 관리 시스템이 뚫려도 백업 자체를 보호하는 아키텍처 필요
