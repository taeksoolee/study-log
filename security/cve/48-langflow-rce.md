# CVE-2025-3248 - Langflow 코드 검증 우회 원격 코드 실행

## 개요

| 항목 | 내용 |
|------|------|
| CVE ID | CVE-2025-3248 |
| CVSS | 9.8 (Critical) |
| 영향 소프트웨어 | Langflow (오픈소스 LLM/AI 에이전트 빌더) |
| 영향 버전 | 1.3.0 미만 |
| 수정 버전 | 1.3.0 이상 |
| 공격 유형 | Remote Code Execution (코드 인젝션) |
| 발견일 | 2025-04-07 |

## 영향 범위 & 심각성

### 왜 치명적인가

Langflow는 **LLM(대규모 언어 모델) 기반 AI 에이전트를 시각적으로 구축**하는 오픈소스 도구다. AI 개발 열풍으로 수많은 개발자와 기업이 빠르게 도입했으며, 이 취약점은:

- AI 도구를 사용하는 **개발자의 로컬 머신**에 직접 영향
- 기업의 AI 파이프라인 인프라가 공격 대상
- 인증 없이 서버에서 임의 코드 실행 가능

### 실제 피해

- 2025년 5월 CISA KEV에 등재 — 실제 악용 확인
- GitHub Stars 50,000+ 프로젝트로 매우 넓은 사용자 기반
- 많은 개발자가 `--host 0.0.0.0`으로 실행하여 네트워크에 노출
- AI/ML 워크로드 서버는 GPU 인스턴스 — 크립토마이닝 타겟으로도 활용

### 영향 규모

- PyPI 다운로드 수백만 건, Docker Hub에서도 널리 사용
- 개발자 로컬, 사내 AI 플랫폼, 클라우드 인스턴스 모두 영향
- AI 스타트업과 R&D 팀에서 프로토타이핑 용도로 광범위 사용

## 취약점 기술 분석

### 근본 원인

Langflow의 `/api/v1/validate/code` 엔드포인트가 **인증 없이 사용자 제공 Python 코드를 실행**한다.

### 기술적 메커니즘

1. **코드 검증 엔드포인트**: 사용자가 작성한 커스텀 컴포넌트 코드를 "검증"하는 API 제공
2. **인증 부재**: 해당 엔드포인트에 인증/인가 체크가 없음
3. **`exec()` 사용**: 검증 과정에서 Python `exec()` 함수로 코드를 직접 실행
4. **샌드박스 없음**: 코드 실행에 어떠한 격리나 제한도 없음

### 취약한 코드 패턴 (개념)

```python
# 취약한 패턴 - 실제 코드 단순화
@router.post("/api/v1/validate/code")
async def validate_code(code: str):
    # 인증 체크 없음!
    exec(code)  # ← 임의 코드 실행
    return {"valid": True}
```

### 왜 발생했나

- "검증"이라는 이름으로 코드를 실행하는 위험한 설계
- 빠른 개발 속도를 위해 보안 검토 없이 API 노출
- AI 도구 개발 생태계의 "빠르게 움직이고 깨뜨려라" 문화

## 공격 시나리오

### 공격 단계

```
1. 발견: Langflow 인스턴스 탐색 (기본 포트 7860)
2. 엔드포인트 접근: /api/v1/validate/code에 POST 요청
3. 코드 주입: Python 역쉘 코드 또는 시스템 명령 전달
4. RCE 달성: 서버 프로세스 권한으로 임의 명령 실행
5. 후속 공격: API 키 탈취, 내부 네트워크 피벗, 크립토마이닝
```

### 개발자 환경 공격 시나리오

- 개발자가 `langflow run --host 0.0.0.0`으로 실행
- 같은 네트워크의 공격자 또는 SSRF를 통해 접근
- 개발자의 SSH 키, AWS 크레덴셜, 소스코드 접근 가능
- AI 학습 데이터, 프롬프트, API 키 탈취

## 방어 방법

### 즉시 조치

1. **업데이트**: Langflow 1.3.0 이상으로 즉시 업그레이드
2. **네트워크 제한**: 0.0.0.0 바인딩 금지, localhost 또는 VPN 뒤에서만 실행
3. **방화벽**: Langflow 포트(7860)에 대한 외부 접근 차단

### 장기 대책

- AI 개발 도구를 전용 격리 환경(컨테이너, VM)에서 실행
- 개발 도구라도 인증 활성화 필수 (`LANGFLOW_SUPERUSER` 설정)
- 네트워크 세그멘테이션으로 개발 환경과 프로덕션 분리
- AI 도구 도입 시 보안 검토 프로세스 수립
- 정기적 의존성 취약점 스캔 (Dependabot, Snyk 등)

### 탐지 방법

- `/api/v1/validate/code` 엔드포인트 접근 로그 모니터링
- Langflow 프로세스의 비정상 자식 프로세스 생성 감지
- 네트워크에서 7860 포트의 외부 접근 시도 탐지

## 교훈

1. **AI 도구도 보안 대상**: "개발 도구"라는 이유로 보안을 소홀히 하면 안 됨
2. **exec()는 절대 사용 금지**: 사용자 입력을 exec/eval에 전달하는 것은 RCE와 동일
3. **인증은 모든 엔드포인트에 기본**: 내부용 API라도 인증 없이 노출하면 공격 표면
4. **개발 환경 ≠ 안전**: 개발자 머신이 뚫리면 프로덕션까지 연쇄 침해
5. **오픈소스 인기 ≠ 보안**: Stars가 많아도 보안 검토가 충분하지 않을 수 있음
6. **AI 버블의 보안 부채**: 빠른 AI 도입 속도에 보안 검토가 따라가지 못하는 현상 경계
