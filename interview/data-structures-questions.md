## 1. 배열과 연결 리스트의 차이는?

**답변:**
배열은 연속 메모리라 인덱스 접근 O(1)·캐시 친화적이지만 중간 삽입/삭제 O(n)·크기 고정. 연결 리스트는 노드가 포인터로 연결돼 삽입/삭제가 O(1)(위치를 알 때)이지만 임의 접근 O(n)·포인터 오버헤드·캐시 비친화. 접근 패턴으로 선택한다.

## 2. 동적 배열은 어떻게 커지나요?

**답변:**
용량이 차면 보통 **2배 크기 새 배열을 할당하고 복사**한다. 개별 push는 가끔 O(n)이지만 **분할 상환(amortized) O(1)**이다(전체 복사 비용이 평균화). 그래서 JS 배열·C++ vector의 push가 평균 상수다.

## 3. ArrayList vs LinkedList 선택은?

**답변:**
임의 접근·끝 추가가 많으면 배열(ArrayList), 양끝/중간 삽입·삭제가 많고 인덱스 접근이 적으면 연결 리스트. 실무에선 캐시 지역성 덕에 배열이 대체로 빠르다. 큐는 배열 기반 링버퍼나 덱을 쓴다.

## 4. 해시 테이블의 동작 원리는?

**답변:**
키를 해시 함수로 정수(버킷 인덱스)에 매핑해 평균 O(1) 삽입/조회/삭제를 제공한다. 충돌(서로 다른 키가 같은 버킷)을 처리하는 메커니즘이 핵심이며, 최악(모두 충돌)은 O(n)이다.

## 5. 해시 충돌을 어떻게 해결하나요?

**답변:**
- **체이닝(separate chaining)**: 각 버킷을 연결 리스트(또는 트리)로 — 충돌 시 이어 붙임. 자바 HashMap은 충돌이 많으면 리스트→트리로 전환.
- **개방 주소법(open addressing)**: 충돌 시 다른 빈 버킷 탐사(선형/이차/이중 해싱). 캐시 친화적이나 삭제·군집(clustering)이 까다롭다.

## 6. 로드 팩터와 리해싱은?

**답변:**
로드 팩터 = 원소 수 / 버킷 수. 임계치(예: 0.75)를 넘으면 충돌이 늘어 성능이 나빠지므로, 버킷을 키우고 **모든 원소를 재배치(리해싱)**한다. 리해싱은 O(n)이지만 가끔이라 분할 상환 O(1)을 유지한다.

## 7. 좋은 해시 함수의 조건은?

**답변:**
빠르고, 키를 버킷에 **고르게 분산**(편향·군집 최소화)하며, 결정적이어야 한다. 비슷한 키가 다른 해시를 갖게 해 충돌을 줄인다. 보안 맥락(비밀번호)에선 충돌 저항·역상 저항이 추가로 필요(암호학적 해시).

## 8. BST의 시간복잡도와 한계는?

**답변:**
균형 잡힌 BST는 탐색/삽입/삭제 O(log n)이지만, 정렬된 데이터를 그냥 넣으면 한쪽으로 치우쳐 **선형(O(n))으로 퇴화**한다. 그래서 자가 균형 트리(AVL/Red-Black)가 필요하다.

## 9. 균형 이진 트리(AVL/Red-Black)란?

**답변:**
삽입/삭제 시 회전(rotation)으로 높이를 O(log n)으로 유지하는 BST. AVL은 더 엄격히 균형(조회 빠름, 회전 잦음), Red-Black은 느슨한 균형(삽입/삭제 빠름)으로 실무 라이브러리(맵/셋)가 주로 채택. 둘 다 최악 O(log n) 보장.

## 10. 힙과 BST의 차이는?

**답변:**
힙은 부모-자식 간 순서만 보장(최소/최대만 O(1) 조회)하고 형제 간 순서는 없어 검색이 O(n). BST는 전체 정렬 순서를 유지해 임의 키 검색 O(log n). "최댓값/최솟값 반복 추출"이면 힙, "정렬·범위 검색"이면 BST.

## 11. B-tree/B+tree는 왜 DB에 쓰나요?

**답변:**
한 노드가 **많은 키와 자식**을 가져 트리 높이가 매우 낮다 → 디스크 I/O(노드 한 번 읽기) 횟수를 최소화한다. B+tree는 데이터를 리프에만 두고 리프를 연결 리스트로 이어 **범위 검색·순차 스캔**에 유리해 DB 인덱스의 표준이다.

## 12. 트라이의 장단점은?

**답변:**
prefix 검색·자동완성이 O(키 길이)로 빠르고 공통 접두사를 공유한다. 단점은 노드마다 자식 포인터로 **메모리를 많이** 쓴다(압축 트라이/래딕스 트리로 완화). 키 비교가 아닌 문자 단위 탐색이라 해시와 다른 강점(범위·prefix).

## 13. 스택과 큐의 활용 예는?

**답변:**
스택(LIFO): 함수 호출(콜스택), DFS, 실행 취소(undo), 괄호 검사, 수식 평가. 큐(FIFO): BFS, 작업 큐·메시지 큐, 캐시(LRU 변형), 프린터 스풀. "최근 것부터"면 스택, "온 순서대로"면 큐.

## 14. 덱(Deque)은 무엇인가요?

**답변:**
양쪽 끝에서 삽입·삭제가 O(1)인 자료구조(double-ended queue). 슬라이딩 윈도우 최댓값(모노토닉 덱), 양방향 작업 큐에 쓴다. 배열 기반 링버퍼나 이중 연결 리스트로 구현.

## 15. 우선순위 큐는 어떻게 구현하나요?

**답변:**
보통 이진 힙(배열 기반)으로 삽입·삭제 O(log n), 최솟값/최댓값 조회 O(1). 다익스트라·작업 스케줄링·K번째 문제에 쓴다. JS는 내장이 없어 직접 구현([코테 가이드 §4](./coding-test-guide.md)).

## 16. 그래프 표현: 인접 행렬 vs 리스트?

**답변:**
인접 행렬은 간선 존재 확인 O(1)·공간 O(V²)로 **밀집 그래프**에. 인접 리스트는 공간 O(V+E)·이웃 순회 효율적으로 **희소 그래프**에(대부분의 실전). 간선이 적으면 리스트가 거의 항상 유리하다.

## 17. 블룸 필터란?

**답변:**
**확률적** 집합 자료구조. 여러 해시로 비트 배열을 세팅해 "확실히 없음" 또는 "아마 있음"을 매우 적은 메모리로 판정한다. 거짓 양성은 있지만 거짓 음성은 없다. 캐시 미스 방지·중복 URL 필터·DB 조회 전 사전 검사에 쓴다.

## 18. LRU와 LFU 캐시의 차이는?

**답변:**
LRU(Least Recently Used)는 **가장 오래 안 쓴** 항목을 제거(해시맵+이중 연결 리스트, O(1)). LFU(Least Frequently Used)는 **가장 적게 쓴** 항목을 제거(빈도 카운트 필요, 구현 복잡). 최근성이 중요하면 LRU, 장기 인기도가 중요하면 LFU.

## 19. 스킵 리스트란?

**답변:**
연결 리스트에 여러 층의 "빠른 차선"을 확률적으로 쌓아 평균 O(log n) 검색/삽입을 얻는 자료구조. 균형 트리보다 구현이 단순하고 동시성에 유리해 일부 DB(Redis sorted set)·인메모리 인덱스에 쓰인다.

## 20. "O(1) 삽입·삭제·랜덤"을 어떻게 만드나요?

**답변:**
배열 + 해시맵(값→인덱스) 조합. 삽입은 배열 끝 추가, 삭제는 **삭제할 원소를 마지막 원소와 swap 후 pop**(O(1)), 랜덤은 배열 인덱스 난수. (LeetCode "Insert Delete GetRandom O(1)".)

## 21. JS의 Map/Set은 내부적으로 무엇인가요?

**답변:**
명세는 구현을 강제하지 않지만 보통 해시 테이블 기반이라 평균 O(1)이다. 일반 객체와 달리 **삽입 순서를 보존**하고, 객체 키를 허용하며, 프로토타입 오염이 없다. 그래서 카운팅·방문 체크에 Object보다 Map/Set이 안전하다.

## 22. 자료구조를 어떻게 고르나요?

**답변:**
필요한 **연산과 그 빈도**로 정한다: 임의 접근→배열, 키 조회→해시, 정렬·범위→균형 트리, 최댓값 반복→힙, prefix→트라이, 양끝→덱, 연결성→유니온 파인드. "어떤 연산을 O(1)/O(log n)으로 만들어야 하는가"를 먼저 묻는다.
