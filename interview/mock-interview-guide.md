## 2. 코딩 테스트 진행 — 말하며 풀기

1. **문제 확인(2~3분)**: 입출력·제약·엣지 케이스를 예시로 되묻기("음수도 들어오나요?").
2. **접근 설명(브루트→최적)**: 바로 코딩 말고 복잡도와 함께 접근을 말로. 면접관이 힌트 줄 여지.
3. **합의 후 구현**: 작게, 변수명 명확히, 말하면서.
4. **테스트**: 예시 + 경계값(빈 입력·1개·최대)을 손으로 추적.
5. **복잡도·개선 언급**: 시간/공간, 더 줄일 여지.

> 핵심은 **사고 과정의 가시화**. 침묵 코딩은 감점. 막히면 "지금 X 때문에 막혔다, Y를 고려 중"이라고 말하라.

## 3. 기술 인터뷰 진행 — 깊이 파고들기

- 답을 **한 문장 결론 → 근거 → 예시/트레이드오프** 순으로. 두괄식.
- 면접관은 "왜?"를 계속 묻는다(꼬리 질문). 외운 정의가 아니라 **이해**를 본다. "이벤트 루프요" 다음 "그럼 마이크로태스크는?"에 답할 수 있어야.
- 모르면 솔직히("정확히는 모르지만 이렇게 추론합니다") + 추론 시도. 지어내지 말 것.
- 자신의 경험·프로젝트와 연결하면 강하다.

## 4. 시스템 디자인 진행 — RADIO

[프론트엔드 SD](./system-design-questions.md)의 RADIO를 따른다.

1. **요구사항 명확화(첫 5분 필수)**: 규모·기능·비기능. 질문 안 하고 그리면 감점.
2. **큰 그림 → 세부**: 컴포넌트/데이터 흐름 먼저, 그다음 깊이.
3. **트레이드오프를 소리 내어**: "X면 A, Y면 B, 여기선 ~니까 A".
4. **병목·확장·실패 대응**: 캐싱·샤딩·장애 처리.
5. **스스로 비판**: "이 설계의 약점은 ~, 개선하면 ~".

> 정답 하나가 없다. **합리적 선택 + 근거 + 트레이드오프 인지**가 점수다.

## 5. 평가 신호 (면접관이 보는 것)

긍정 신호:
- 요구사항을 먼저 명확히 한다.
- 막혔을 때 사고를 소리 내고, 힌트를 잘 받아들인다.
- 트레이드오프를 인지하고 결정에 근거를 댄다.
- 자신의 코드/주장을 스스로 검증·비판한다.
- 모르는 것을 솔직히 인정하고 추론한다.

부정 신호:
- 문제를 확인 안 하고 가정으로 돌진.
- 침묵하며 혼자 코딩.
- 외운 답만 읊고 "왜"에 막힘.
- 방어적(피드백 거부)·독선적.
- 지어내기(모르면서 아는 척).

## 6. 흔한 탈락 사유

- **기초 부실**: 화려한 주제는 알지만 클로저·박스모델·HTTP 같은 기본이 흔들림.
- **소통 부재**: 답은 맞는데 설명을 못 함(시니어일수록 치명적).
- **엣지 케이스 무시**: 빈 입력·null·경계에서 깨짐.
- **트레이드오프 무지**: "무조건 X가 좋다"식 단정.
- **자기 인식 부족**: 실패/갈등 질문에 "그런 적 없다".

## 7. 준비 로드맵 & 이 저장소 활용법

```
1주차: 기초 점검  → javascript / frontend / html-css 질문집 + CS
2주차: 코테 패턴  → algorithms/patterns 1~26 + 코테 대표문제 1~3
3주차: 심화      → JS심화 / React / TS / 자료구조 / SQL 질문집
4주차: 설계·행동  → 시스템 디자인(FE+백엔드) + 행동 심화 + 모의면접
상시:  약점 노트  → 틀린 질문·막힌 문제를 따로 정리해 반복
```

활용 팁:
- 질문집은 **답을 가리고 먼저 말로 답한 뒤** 비교(인출 연습, retrieval practice).
- 패턴 문서는 **대표문제로 손으로 구현**해 봐야 체화된다.
- "면접 포인트" Q&A를 **소리 내어** 설명(설명 못 하면 이해 못 한 것).
- 모의 면접은 타이머 + 녹음으로 — 군더더기·침묵을 객관적으로 점검.

> 가장 큰 ROI: **기초를 말로 설명하는 연습** + **틀린 것 반복**. 새 주제 욕심보다 아는 것을 정확히·명료하게 전달하는 게 합격을 가른다.
