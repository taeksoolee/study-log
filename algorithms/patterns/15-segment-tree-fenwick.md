# 15. 세그먼트 트리 & 펜윅 트리 (Segment Tree / BIT)

> [누적합](./11-prefix-sum.md)은 구간 질의 O(1)이지만 갱신이 O(n)이다. **질의와 갱신이 둘 다 잦으면** 두 연산을 모두 O(log n)으로 처리하는 트리 구조가 필요하다.

## 1. 왜 필요한가: 누적합의 한계

| | 구간 질의 | 점 갱신 |
|--|----------|--------|
| 단순 배열 | O(n) | O(1) |
| 누적합 | O(1) | O(n) (전체 재계산) |
| **세그먼트/펜윅 트리** | **O(log n)** | **O(log n)** |

"i번째 값을 바꾸고 [l, r] 합을 묻는" 연산이 번갈아 수만 번 들어오면 누적합은 갱신마다 O(n)이라 터진다. 세그먼트 트리가 정답.

---

## 2. 세그먼트 트리 — 구조

배열 구간을 **이진 트리로 분할**한다. 리프는 원소, 내부 노드는 자식 구간의 병합값(합/최소/최대/GCD…)을 들고 있다.

```
        [0..3] 합=10
        /          \
   [0..1]=3      [2..3]=7
   /     \        /     \
[0]=1  [1]=2  [2]=3  [3]=4
```

- 높이 O(log n) → 질의·갱신이 루트~리프 한 경로라 O(log n).
- 합 외에 최소/최대/GCD 등 **결합법칙이 성립하는 연산**이면 무엇이든 가능(이게 누적합보다 일반적인 이유 — 누적합은 "역연산 가능한" 합/곱만 됨, 최소/최대는 불가).

## 3. 세그먼트 트리 — 구현 (구간 합)

배열 기반(1-indexed, 크기 2n) 반복 구현.

```javascript
class SegTree {
  constructor(arr) {
    this.n = arr.length;
    this.t = new Array(2 * this.n).fill(0);
    for (let i = 0; i < this.n; i++) this.t[this.n + i] = arr[i]; // 리프
    for (let i = this.n - 1; i > 0; i--)                          // 내부 노드
      this.t[i] = this.t[2*i] + this.t[2*i+1];
  }
  update(i, val) {            // i번째를 val로
    let p = i + this.n;
    this.t[p] = val;
    for (p >>= 1; p > 0; p >>= 1)
      this.t[p] = this.t[2*p] + this.t[2*p+1];  // 부모로 전파
  }
  query(l, r) {              // [l, r) 합 (반열림)
    let res = 0;
    for (l += this.n, r += this.n; l < r; l >>= 1, r >>= 1) {
      if (l & 1) res += this.t[l++];
      if (r & 1) res += this.t[--r];
    }
    return res;
  }
}
```

## 4. 펜윅 트리 (BIT) — 더 간결한 대안

**구간 합 갱신/질의만** 필요하면 펜윅 트리(Binary Indexed Tree)가 더 짧고 빠르다. 핵심은 `i & -i`(최하위 비트)로 담당 구간을 점프하는 것.

```javascript
class BIT {
  constructor(n) { this.n = n; this.t = new Array(n + 1).fill(0); } // 1-indexed
  update(i, delta) {                 // i번째에 delta 더하기
    for (; i <= this.n; i += i & -i) this.t[i] += delta;
  }
  prefix(i) {                        // [1, i] 합
    let s = 0;
    for (; i > 0; i -= i & -i) s += this.t[i];
    return s;
  }
  range(l, r) { return this.prefix(r) - this.prefix(l - 1); } // [l, r]
}
```

> 세그먼트 트리보다 코드가 절반이고 상수가 작다. 단 최소/최대처럼 역연산이 없는 질의엔 부적합(합·XOR 등 역연산 가능한 것만).

---

## 5. Lazy Propagation — 구간 갱신

"구간 [l, r] 전체에 +v"를 O(log n)에 하려면 갱신을 **미뤄서 전파**한다. 노드에 "아직 자식에 안 내린 갱신"을 lazy 값으로 저장하고, 그 노드를 방문할 때만 자식에 내린다.

- 점 갱신 + 구간 질의 → 기본 세그먼트 트리.
- **구간 갱신 + 구간 질의 → lazy propagation** 필수. (구현은 길어지므로 개념만: 방문 시 `push down`으로 자식에 lazy 적용.)

---

## 6. 선택 기준

| 요구 | 선택 |
|------|------|
| 구간 합 질의만 (갱신 없음) | 누적합 |
| 점 갱신 + 구간 합 | 펜윅 트리(BIT) |
| 점 갱신 + 구간 최소/최대/GCD | 세그먼트 트리 |
| 구간 갱신 + 구간 질의 | 세그먼트 트리 + lazy propagation |

## 7. 면접 포인트

**Q. 누적합 대신 세그먼트 트리를 쓰는 경우는?**
> 갱신과 구간 질의가 둘 다 빈번할 때. 누적합은 갱신마다 O(n) 재계산이 필요하지만 세그먼트 트리는 갱신·질의 모두 O(log n)이다. 또 최소/최대/GCD처럼 역연산이 없어 누적합으로 못 푸는 질의도 처리한다.

**Q. 세그먼트 트리로 가능한 질의의 조건은?**
> 결합법칙이 성립하는 병합 연산(합, 최소, 최대, GCD, 곱 등). 두 자식 구간의 답을 부모 구간의 답으로 합칠 수 있어야 한다.

**Q. 펜윅 트리(BIT)와 세그먼트 트리의 차이는?**
> BIT는 구간 합처럼 역연산이 가능한 연산에만 쓰지만 코드가 짧고 상수가 작다. 세그먼트 트리는 최소/최대 등 더 일반적인 질의와 lazy propagation을 통한 구간 갱신까지 지원하지만 구현이 길다. 합만 필요하면 BIT가 실전에서 유리하다.

**Q. lazy propagation은 무엇을 해결하나요?**
> 구간 전체 갱신을 O(log n)에 처리한다. 갱신을 즉시 모든 리프에 내리면 O(n)이라, 노드에 미뤄둔 갱신(lazy)을 저장하고 그 노드를 방문할 때만 자식으로 내려보내(push down) 구간 갱신+구간 질의를 모두 O(log n)으로 만든다.

**Q. `i & -i`는 펜윅 트리에서 무엇을 의미하나요?**
> 정수 i의 최하위 1비트(LSB)다. BIT에서 각 인덱스가 담당하는 구간의 길이이자, 부모/다음 노드로 점프하는 보폭이다. 갱신은 이 비트를 더하며 위로, 질의는 빼며 아래로 이동한다.
