## 1. 그리디가 옳은 조건

그리디(매 단계 지역 최적 선택)는 두 조건을 만족할 때 전역 최적을 보장한다.

- **탐욕적 선택 속성(greedy choice property)**: 지역 최적 선택이 전역 최적의 일부가 될 수 있다.
- **최적 부분 구조(optimal substructure)**: 부분 문제의 최적해가 전체 최적해를 구성.

> 그리디는 빠르지만(보통 정렬 후 O(n log n)) **틀리기 쉽다**. "되는 것 같다"가 아니라 증명(교환 논증·귀류법)이 있어야 한다. 동전 거스름돈도 동전 체계에 따라 그리디가 틀린다(DP 필요).

---

## 2. 교환 논증 (Exchange Argument)

그리디 정당성의 표준 증명법: **"최적해가 그리디와 다르다면, 그리디 선택으로 바꿔도 더 나빠지지 않음"**을 보여, 그리디 해가 최적과 같음을 논증.

예(활동 선택): "종료 시각이 가장 이른 활동을 고르는 게 최적"의 증명 — 어떤 최적해의 첫 활동을 더 일찍 끝나는 그리디 활동으로 바꿔도 충돌이 안 생기고 활동 수가 줄지 않는다 → 그리디 선택을 포함하는 최적해가 존재.

---

## 3. 구간 스케줄링 (활동 선택)

겹치지 않게 최대한 많은 활동을 선택. **종료 시각 오름차순 정렬** 후, 충돌 안 하는 것을 탐욕적으로 채택.

```javascript
function maxActivities(intervals) {     // [start, end]
  intervals.sort((a, b) => a[1] - b[1]); // 종료 빠른 순 (핵심!)
  let count = 0, lastEnd = -Infinity;
  for (const [s, e] of intervals) {
    if (s >= lastEnd) { count++; lastEnd = e; } // 충돌 안 하면 채택
  }
  return count;
}
// O(n log n)
```

> 왜 "시작 빠른"·"짧은" 순이 아니라 "**종료 빠른**" 순인가? 가장 빨리 끝나는 활동을 고르면 뒤에 최대한 많은 여지를 남기기 때문(교환 논증으로 증명됨).

## 4. 최소 회의실 / 작업 마감

- **최소 회의실 수**: 시작·종료를 분리 정렬해 스위프(동시 진행 최대값) 또는 종료 시각 최소 힙. ([스위프 예](../../interview/coding-test-problems-2.md))
- **마감 있는 작업 스케줄링(이익 최대)**: 이익 내림차순 정렬 후, 각 작업을 마감 직전 빈 슬롯에 배치(유니온 파인드로 빈 슬롯 탐색 가속).
- **최소 지각(Lateness)**: 마감 이른 순(EDF, Earliest Deadline First)으로 처리하면 최대 지각 최소화.

## 5. 허프만 코딩

문자 빈도에 따라 **가변 길이 접두 부호**를 만들어 전체 인코딩 길이를 최소화(무손실 압축). 그리디 + 최소 힙.

```javascript
function huffman(freq) {                 // freq: [[char, count], ...]
  const pq = new MinHeap();              // 빈도 기준 최소 힙
  for (const [c, f] of freq) pq.push({ f, c });
  while (pq.size() > 1) {
    const a = pq.pop(), b = pq.pop();    // 가장 빈도 낮은 둘
    pq.push({ f: a.f + b.f, left: a, right: b }); // 합쳐 새 노드
  }
  return pq.pop();                       // 루트 = 허프만 트리
}
// O(n log n). 빈도 낮은 문자에 긴 코드 → 평균 길이 최소
```

> 핵심 그리디: **가장 빈도 낮은 두 노드를 반복해서 합친다**. 빈번한 문자가 짧은 코드를 갖게 되어 최적. 접두 부호라 디코딩이 모호하지 않다.

## 6. 그리디 vs DP 판별

| | 그리디 | DP |
|--|--------|-----|
| 선택 | 매 단계 한 번 결정, 되돌림 X | 모든 경우 고려, 최적 결합 |
| 속도 | 빠름(정렬 O(n log n)) | 느림(상태 수만큼) |
| 적용 | 탐욕 선택 속성 성립 시 | 겹치는 부분 문제 |
| 위험 | 틀리기 쉬움(증명 필요) | 항상 정확하나 무거움 |

> 판별: 그리디가 맞는지 **반례를 찾아보고**, 못 찾으면 교환 논증을 시도. 안 되면 DP. 동전 거스름돈처럼 동전 체계에 따라 그리디↔DP가 갈린다.

## 7. 면접 포인트

**Q. 그리디가 최적임을 어떻게 보장하나요?**
> 탐욕적 선택 속성과 최적 부분 구조가 성립해야 한다. 정당성은 보통 교환 논증으로 증명한다 — 최적해를 그리디 선택으로 바꿔도 나빠지지 않음을 보여 그리디 해가 최적과 같음을 논증한다. 증명 없이 직관만으로 그리디를 쓰면 틀리기 쉽다.

**Q. 활동 선택에서 왜 종료 시각 기준으로 정렬하나요?**
> 가장 빨리 끝나는 활동을 고르면 남은 시간에 더 많은 활동을 넣을 여지가 최대가 되기 때문이다. 시작 빠른 순이나 짧은 순은 반례가 있고, 종료 빠른 순만 교환 논증으로 최적이 증명된다.

**Q. 허프만 코딩의 그리디 선택은?**
> 빈도가 가장 낮은 두 노드를 반복해서 합쳐 트리를 만든다. 그 결과 빈번한 문자가 짧은 접두 부호를 갖게 되어 전체 인코딩 길이가 최소가 된다. 최소 힙으로 O(n log n).

**Q. 그리디와 DP를 어떻게 구분하나요?**
> 매 단계 한 번의 지역 최적 선택으로 전역 최적이 되면 그리디(빠름), 그렇지 않고 여러 선택을 비교·결합해야 하면 DP다. 반례를 찾아 그리디가 깨지면 DP로 간다. 동전 거스름돈이 동전 체계에 따라 갈리는 대표 예다.

**Q. 마감이 있는 작업에서 최대 지각을 최소화하려면?**
> 마감이 이른 순(EDF)으로 처리한다. 교환 논증으로, 마감 늦은 작업을 먼저 하면 최대 지각이 줄지 않음을 보일 수 있다.
