## 1. 개념: 전처리로 구간 질의 O(1)

배열의 임의 구간 `[l, r]` 합을 여러 번 물어볼 때, 매번 더하면 질의당 O(n)이다. **누적합을 한 번 O(n)으로 전처리**해 두면 각 질의를 **O(1)**로 답한다.

```
원본 a:      [3, 1, 4, 1, 5]
누적합 P:  [0, 3, 4, 8, 9, 14]   (P[i] = a[0..i-1]의 합)
구간 [l,r] 합 = P[r+1] - P[l]
```

핵심 아이디어: "구간 합 = 두 누적합의 차". 슬라이딩 윈도우가 *연속 구간을 밀며* 갱신한다면, 누적합은 *임의 구간*을 즉시 답한다.

## 2. 1차원 누적합

```javascript
function buildPrefix(a) {
  const P = new Array(a.length + 1).fill(0); // P[0]=0 센티넬
  for (let i = 0; i < a.length; i++) {
    P[i + 1] = P[i] + a[i];
  }
  return P;
}

// 구간 [l, r] (양끝 포함) 합 — O(1)
function rangeSum(P, l, r) {
  return P[r + 1] - P[l];
}

const a = [3, 1, 4, 1, 5];
const P = buildPrefix(a);
rangeSum(P, 1, 3); // a[1]+a[2]+a[3] = 1+4+1 = 6
```

> `P[0] = 0` 센티넬을 두면 `l = 0`일 때도 `P[l]` 인덱스 예외 없이 깔끔하게 처리된다.

## 3. 2차원 누적합 (포함-배제)

행렬에서 직사각형 영역 합을 O(1)에 구한다. **포함-배제(inclusion-exclusion)** 원리를 쓴다.

```javascript
function build2D(grid) {
  const R = grid.length, C = grid[0].length;
  const P = Array.from({length: R + 1}, () => new Array(C + 1).fill(0));
  for (let i = 1; i <= R; i++)
    for (let j = 1; j <= C; j++)
      P[i][j] = grid[i-1][j-1] + P[i-1][j] + P[i][j-1] - P[i-1][j-1];
  return P;
}

// (r1,c1)~(r2,c2) 직사각형 합 (0-based, 양끝 포함)
function sum2D(P, r1, c1, r2, c2) {
  return P[r2+1][c2+1] - P[r1][c2+1] - P[r2+1][c1] + P[r1][c1];
}
```

```
큰 사각형 - 위 - 왼쪽 + 겹쳐 뺀 부분(중복 보정)
```

## 4. 차분 배열 (Difference Array)

누적합의 **역연산**. "구간 `[l, r]`에 +v를 더하는 갱신"이 여러 번 들어올 때, 매 갱신을 O(1)로 기록하고 마지막에 한 번 누적합으로 복원한다.

```javascript
function rangeUpdates(n, ops) {
  const diff = new Array(n + 1).fill(0);
  for (const [l, r, v] of ops) {  // 각 갱신 O(1)
    diff[l] += v;
    diff[r + 1] -= v;             // 구간 끝 다음에서 효과 상쇄
  }
  const res = new Array(n).fill(0);
  res[0] = diff[0];
  for (let i = 1; i < n; i++) res[i] = res[i-1] + diff[i]; // 누적 복원
  return res;
}
// ops = [[1,3,2],[2,4,3]] → 구간 갱신 m개를 O(n+m)에 반영
```

> 구간 갱신이 많고 질의는 마지막에 한 번이면 차분 배열, 갱신 없이 구간 질의만 많으면 누적합. 갱신+질의가 둘 다 빈번하면 펜윅 트리/세그먼트 트리로 간다.

## 5. 응용: 합이 K인 부분 배열 (해시 결합)

누적합 + 해시맵의 고전 조합. "합이 정확히 K인 연속 부분 배열의 개수"를 O(n)에 센다.

```javascript
function subarraySum(nums, k) {
  const count = new Map([[0, 1]]); // 누적합 0이 1번 (빈 prefix)
  let prefix = 0, ans = 0;
  for (const x of nums) {
    prefix += x;
    // prefix - (이전 누적합) = k  →  이전 누적합 = prefix - k
    ans += count.get(prefix - k) ?? 0;
    count.set(prefix, (count.get(prefix) ?? 0) + 1);
  }
  return ans;
}
```

> 음수가 섞여 슬라이딩 윈도우가 안 통할 때, "누적합의 차 = 구간합" 성질 + 해시로 O(n)에 푼다. 빈출 패턴.

## 6. 시간복잡도 비교

| 방식 | 전처리 | 구간 질의 | 구간 갱신 |
|------|--------|----------|----------|
| 매번 합산 | 없음 | O(n) | O(1) |
| 누적합 | O(n) | **O(1)** | O(n)(재계산) |
| 차분 배열 | O(n+m) | O(n)(복원 후) | **O(1)** |
| 펜윅/세그먼트 트리 | O(n) | O(log n) | O(log n) |

## 7. 면접 포인트

**Q. 누적합과 슬라이딩 윈도우의 차이는?**
> 슬라이딩 윈도우는 연속 구간을 한 칸씩 밀며 들어오고 나가는 원소만 갱신한다(주로 가변/고정 윈도우 최적화). 누적합은 전처리 후 *임의의* 구간 `[l,r]` 합을 `P[r+1]-P[l]`로 O(1)에 답한다. 질의 구간이 매번 다를 때 누적합이 유리하다.

**Q. `P[0]=0` 센티넬을 두는 이유는?**
> `l=0` 같은 경계에서 `P[l]` 접근을 예외 없이 처리하기 위해서다. `P[i]`를 "처음 i개의 합"으로 정의하면 구간 합이 깔끔하게 `P[r+1]-P[l]`이 된다.

**Q. 차분 배열은 언제 쓰나요?**
> 구간 `[l,r]`에 값을 더하는 갱신이 여러 번 들어오고 최종 결과를 한 번 보면 될 때. `diff[l]+=v, diff[r+1]-=v`로 각 갱신을 O(1)에 기록하고 마지막에 누적합으로 복원해 전체 O(n+m). 누적합의 역연산이다.

**Q. 합이 K인 부분 배열을 음수 포함 배열에서 O(n)에 세려면?**
> 슬라이딩 윈도우는 음수에서 단조성이 깨져 안 통한다. 누적합을 누적하면서 "현재 prefix - K"가 이전에 몇 번 나왔는지 해시맵으로 세면 O(n)에 해결된다.

**Q. 구간 질의와 갱신이 둘 다 빈번하면?**
> 누적합은 갱신 시 재계산이 O(n)이라 비효율. 펜윅 트리(BIT)나 세그먼트 트리로 질의·갱신 모두 O(log n)에 처리한다.
