# 05. `position: sticky` 투명 배경 겹침 & CSS 변수 테마

> 실전 배경: 다크모드를 도입한 뒤, 좌측 고정(fixed) 컬럼이 있는 테이블에서
> **가로 스크롤을 하면 고정 컬럼 뒤로 다른 셀이 비쳐 겹쳐 보였다.**
> 라이트모드에선 멀쩡했다. 원인은 고정 컬럼의 배경이 **투명**이었기 때문.

## 1. 왜 sticky/fixed 컬럼은 배경이 있어야 하나

테이블의 고정 컬럼은 `position: sticky`(또는 `fixed`)로 구현된다. sticky 요소는 스크롤 시 **다른 콘텐츠 위에 떠 있는(overlay) 상태**가 된다. 그런데 배경이 투명하면, 그 아래로 스크롤되어 지나가는 셀들이 **그대로 비쳐 보인다.**

```css
/* 고정 컬럼 */
.fixed-col {
  position: sticky;
  left: 0;
  /* background 없음 → 스크롤되는 셀이 투과되어 겹쳐 보임 */
}
```

sticky는 요소를 흐름에서 들어올리지만 **뒤 배경을 가려주진 않는다.** "떠 있는 요소는 스스로 불투명 배경을 가져야 뒤를 가린다"가 핵심이다. 이건 툴팁·드롭다운·헤더 등 모든 overlay성 요소에 공통되는 원리다.

## 2. 왜 라이트모드에선 안 보였나

라이트모드 코드에는 배경이 `#FFFFFF`로 **명시**돼 있었다.

```js
// customCell (라이트모드) — 흰 배경이 있어서 뒤를 가려줌
customCell: () => ({ style: 'background-color: #FFFFFF' })
```

다크모드를 추가하면서 fixed 컬럼의 배경을 빈 문자열로 두는 분기가 생겼다.

```js
// 다크모드 분기 — 배경이 투명 → 겹침 발생
customCell: () => ({ style: isDark ? '' : 'background-color: #FFFFFF' })
```

즉 버그의 본질은 "다크모드"가 아니라 **"다크모드 경로에서만 배경 명시가 빠진 것"**이다. 라이트모드는 우연히 흰 배경 덕에 문제가 가려져 있었을 뿐이다. **버그가 특정 테마에서만 보인다고 그 테마의 문제라고 단정하면 안 된다** — 조건 분기 중 하나에서만 불변식(overlay는 불투명 배경을 가진다)이 깨진 것이다.

## 3. 해법: CSS 변수로 불투명 배경 보장

두 분기 모두에 불투명 배경을 보장하되, 하드코딩 색이 아니라 **테마에 반응하는 CSS 변수**를 쓴다.

```js
// 두 모드 모두 불투명 배경 — 값은 테마 변수로
customCell: () => ({ style: 'background-color: var(--colorBgContainer)' })
```

`var(--colorBgContainer)`는 테마에 따라 자동으로 다른 값을 갖는다(라이트 `#ffffff`, 다크 `#141414`). 그래서 **분기 자체가 필요 없어지고**, 테마가 늘어나도 이 코드는 그대로 동작한다. `isDark ? A : B` 같은 JS 분기를 CSS 변수로 밀어내면 조건 분기가 사라진다.

> 남은 하드코딩(`isDark ? 'var(--colorBgContainer)' : '#FFFFFF'`)이 있다면 일관성을 위해 변수로 통일하는 게 이상적이지만, 동작이 이미 맞다면 별도 정리로 미룰 수 있다. **동작 수정과 스타일 통일을 한 커밋에 섞지 않는다.**

## 4. CSS 커스텀 프로퍼티로 테마를 전환하는 구조

테마 전환의 핵심은 **컴포넌트는 변수만 참조하고, 변수 값은 한 곳에서 갈아끼우는 것**이다.

```css
/* :root 또는 테마 컨테이너에 변수 정의 */
:root {
  --colorBgContainer: #ffffff;
  --colorText: #1f1f1f;
}
:root[data-theme='dark'] {
  --colorBgContainer: #141414;
  --colorText: #e6e6e6;
}
```

```ts
// 토글 시 값의 소스만 바꾼다 (컴포넌트 CSS는 그대로)
watch(isDark, (dark) => {
  document.documentElement.dataset.theme = dark ? 'dark' : 'light';
  // 또는 CSS 변수를 직접 세팅
  document.documentElement.style.setProperty(
    '--colorBgContainer', dark ? '#141414' : '#ffffff',
  );
});
```

- **컴포넌트는 `var(--colorBgContainer)`만 참조** → 색 값을 몰라도 된다.
- CSS 변수는 **상속**되고 **런타임에 바뀌면 즉시 리페인트**된다. 그래서 클래스 토글만으로 전체 테마가 전환된다.
- 테마 키(예: localStorage `theme`)는 **하드코딩 문자열 대신 상수**(`storageKeys.THEME`)로 관리해 오타·불일치를 막는다.

관련 개념은 [모던 CSS](../frontend/html-css/05-modern-css.md)와 [Reflow & Repaint](../browser/05-reflow-repaint.md)에서 다룬다. (배경색 변경은 레이아웃을 바꾸지 않으므로 reflow 없이 repaint만 유발한다.)

## 5. 면접 포인트

**Q. `position: sticky` 요소 뒤로 다른 콘텐츠가 비쳐 보이는 이유는?**
> sticky 요소는 스크롤 시 다른 콘텐츠 위에 떠 있는 상태가 되는데, 배경이 투명하면 아래로 지나가는 콘텐츠가 그대로 투과되어 겹쳐 보인다. 떠 있는 요소는 스스로 불투명 배경을 가져야 뒤를 가린다. 고정 테이블 컬럼, sticky 헤더 등에서 흔한 버그다.

**Q. 버그가 다크모드에서만 보였다. 다크모드의 문제일까?**
> 아니다. 이 경우 라이트모드는 배경색이 명시돼 우연히 가려졌고, 다크모드 분기에서만 배경 명시가 빠져 있었다. 특정 조건에서만 드러나는 버그는 "그 조건의 문제"가 아니라 "그 조건 분기에서 불변식이 깨진 것"으로 봐야 한다.

**Q. CSS 변수(커스텀 프로퍼티)로 테마를 전환하면 뭐가 좋은가요?**
> 컴포넌트는 var(--token)만 참조하고 값의 소스는 한 곳에서 바꾸므로, 테마가 늘어도 컴포넌트 CSS를 안 건드린다. 변수는 상속되고 런타임 변경 시 즉시 반영돼 클래스/속성 토글만으로 전체가 전환된다. isDark 같은 JS 분기를 CSS로 밀어내 분기 자체를 없앨 수 있다.

**Q. 테마를 배경색만 바꾸는 건 reflow인가 repaint인가?**
> 배경색은 레이아웃(위치·크기)에 영향이 없으므로 reflow 없이 repaint만 일어난다. 반대로 크기·위치를 바꾸는 변경은 reflow를 유발하므로 테마 전환에서 그런 속성 변경은 피하는 게 좋다.
