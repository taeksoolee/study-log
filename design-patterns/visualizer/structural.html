어댑터 패턴 (Adapter)
호환되지 않는 인터페이스를 가진 클래스들이 함께 동작할 수 있도록 변환기(어댑터)를 제공합니다.
클라이언트는 NewInterface만 알고, Adapter가 내부적으로 OldInterface를 호출합니다.

어댑터 패턴 활용 예시
// OldInterface (기존 라이브러리)
class LegacyPrinter {
  printDocument(xml: string): void { ... }
}

// NewInterface (클라이언트가 기대하는 인터페이스)
interface ModernPrinter {
  print(json: string): void;
}

// Adapter
class PrinterAdapter implements ModernPrinter {
  constructor(private legacy: LegacyPrinter) {}
  print(json: string): void {
    const xml = convertJsonToXml(json);
    this.legacy.printDocument(xml);
  }
}
브릿지 패턴 (Bridge)
추상화(Abstraction)와 구현(Implementation)을 분리하여 독립적으로 변형할 수 있게 합니다.
두 계층이 브릿지(참조)로 연결되어, 조합 폭발 문제를 해결합니다.

객체들을 트리 구조로 구성하여 단일 객체와 복합 객체를 동일하게 다룰 수 있게 합니다.

파사드 패턴 (Facade)
복잡한 서브시스템에 단순화된 인터페이스를 제공합니다.
클라이언트는 복잡한 내부를 알 필요 없이 Facade만 사용하면 됩니다.

// playVideo() 버튼을 눌러 파사드 동작을 확인하세요
VideoFacade 구현 예시
class VideoFacade {
  constructor(
    private decoder: VideoDecoder,
    private mixer: AudioMixer,
    private buffer: BufferManager
  ) {}

  playVideo(file: string): void {
    // 클라이언트 대신 복잡한 순서를 처리
    this.buffer.allocate(file);
    this.decoder.decode(file);
    this.mixer.mix();
  }
}
플라이웨이트 패턴 (Flyweight)
많은 수의 유사한 객체를 효율적으로 지원하기 위해 공유(내재 상태)를 사용합니다.
내재 상태(intrinsic)는 공유, 외재 상태(extrinsic)는 각 객체가 유지합니다.
0
총 객체 수
0

0

🗂 플라이웨이트 풀 (공유 내재 상태)
아직 생성된 플라이웨이트 없음
내재 상태 (공유됨)
• 객체 타입 (tree/bullet/particle)
• 색상 (color)
• 텍스처 (texture)
외재 상태 (개별 유지)
• 위치 (x, y)
• 크기 (scale)
• 생성 시각 (timestamp)

가상 프록시 (Virtual)
실제 객체의 생성을 지연시킴. 무거운 객체의 lazy initialization에 사용.
보호 프록시 (Protection)
접근 권한을 제어. 권한 없는 클라이언트의 접근을 차단.
캐싱 프록시 (Caching)
결과를 캐싱하여 동일 요청의 반복 처리를 방지.
원격 프록시 (Remote)
원격 서버의 객체에 대한 로컬 대리자. 네트워크 세부사항 숨김.
