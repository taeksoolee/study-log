GOF 생성 패턴 (Creational Patterns) 시각화

Gang of Four 디자인 패턴 — 객체 생성에 관한 5가지 패턴을 인터랙티브하게 학습합니다.

싱글턴 패턴 (Singleton Pattern)
클래스의 인스턴스가 오직 하나만 존재하도록 보장하고, 어디서든 그 인스턴스에 접근할 수 있는 전역 접근점을 제공합니다.
핵심 아이디어: 생성자를 private으로 막고, getInstance() 메서드를 통해서만 인스턴스를 얻을 수 있도록 합니다. 두 번째 호출부터는 새 객체를 만들지 않고 처음 만든 객체를 반환합니다.
UML 클래스 다이어그램

– instance: Singleton
– id: string
– createdAt: Date
– Singleton()  [private]
+ getInstance(): Singleton
+ getId(): string
+ getInfo(): object
class Singleton { static #instance = null; #id; // private 생성자 constructor() { if (Singleton.#instance) { throw new Error("직접 생성 불가"); } this.#id = crypto.randomUUID().slice(0,8); } static getInstance() { if (!Singleton.#instance) { Singleton.#instance = new Singleton(); } return Singleton.#instance; } }

팩토리 메서드 패턴 (Factory Method Pattern)
객체를 생성하기 위한 인터페이스를 정의하되, 어떤 클래스를 인스턴스화할지는 서브클래스가 결정하도록 위임합니다. 객체 생성 코드를 사용하는 코드로부터 분리할 수 있습니다.
Creator 클래스는 factoryMethod()를 선언하고, ConcreteCreator가 이를 오버라이드해 구체적인 Product를 반환합니다.

구조 이해: Creator와 Product의 관계
Creator (팩토리)
  • 추상 메서드 factoryMethod() 선언
  • Product를 사용하는 로직 포함
  • 어떤 Product를 만들지는 모름
ConcreteCreator (구체 팩토리)
  • factoryMethod() 오버라이드
  • 구체적인 Product 반환
  • 생성 방법을 캡슐화
Product (인터페이스)
  • 모든 제품의 공통 인터페이스
  • Creator는 이 인터페이스만 알면 됨
  • 개방-폐쇄 원칙 (OCP) 준수
추상 팩토리 패턴 (Abstract Factory Pattern)
관련된 또는 의존적인 객체들의 패밀리를 구체적인 클래스를 지정하지 않고도 생성할 수 있는 인터페이스를 제공합니다. 팩토리 메서드를 여러 개 묶은 형태입니다.
예시: UI 테마 시스템 — LightTheme 팩토리는 밝은 Button과 Checkbox를, DarkTheme 팩토리는 어두운 Button과 Checkbox를 생성합니다. 클라이언트는 어떤 팩토리를 사용하는지에 따라 일관된 제품군을 얻습니다.

팩토리 메서드 vs 추상 팩토리 비교
팩토리 메서드
  • 단일 제품을 생성
  • 서브클래스에서 생성 방법 결정
  • 상속(Inheritance) 기반
  • 메서드 하나가 오버라이드됨
추상 팩토리
  • 관련 제품군(Family)을 생성
  • 팩토리 객체를 전달(위임)
  • 합성(Composition) 기반
  • 팩토리 인터페이스 전체를 교체
빌더 패턴 (Builder Pattern)
복잡한 객체를 단계별로 구성할 수 있게 해주는 패턴입니다. 동일한 구성 과정으로 서로 다른 표현을 만들 수 있습니다. 생성자에 많은 매개변수가 필요한 객체에 특히 유용합니다.
예시: 집 짓기 — 기초(Foundation) → 벽(Walls) → 지붕(Roof) 순으로 단계를 밟아 최종 House 객체를 완성합니다.

class Director { construct(builder) { // 빌더의 단계를 순서대로 호출 return builder .buildFoundation() // Step 1: 기초 공사 .buildWalls() // Step 2: 벽 세우기 .buildRoof() // Step 3: 지붕 얹기 .getResult(); // 최종 House 반환 } } // 사용 예 const director = new Director(); const builder = new ConcreteHouseBuilder(); const house = director.construct(builder);
프로토타입 패턴 (Prototype Pattern)
기존 객체를 복사하여 새로운 객체를 만드는 패턴입니다. 복잡한 초기화 로직 없이 동일한 구조의 객체를 빠르게 생성할 수 있습니다. 클래스에 의존하지 않고 복사본을 만들 수 있어 유연합니다.
핵심: clone() 메서드를 통해 자기 자신을 복사합니다. 깊은 복사(Deep Copy)와 얕은 복사(Shallow Copy)의 차이를 이해하는 것이 중요합니다.

깊은 복사 vs 얕은 복사

깊은 복사 (Deep Copy)

중첩된 객체/배열까지 모두 새로 생성합니다. 복사본을 수정해도 원본에 영향이 없습니다. 

// 깊은 복사 예시
const original = {
  name: "A",
  tags: ["x", "y"]
};

// JSON 방법
const copy = JSON.parse(
  JSON.stringify(original)
);

// structuredClone (모던)
const copy2 = structuredClone(original);

copy.tags.push("z");
// original.tags → ["x", "y"] ✓ 영향 없음

얕은 복사 (Shallow Copy)

최상위 레벨만 복사하고, 중첩 객체는 참조를 공유합니다. 복사본의 내부 객체를 수정하면 원본도 바뀝니다. 

// 얕은 복사 예시
const original = {
  name: "A",
  tags: ["x", "y"]
};

// Object.assign
const copy = Object.assign({}, original);

// 스프레드 연산자
const copy2 = { ...original };

copy.tags.push("z");
// original.tags → ["x", "y", "z"] ⚠️ 영향 있음!
