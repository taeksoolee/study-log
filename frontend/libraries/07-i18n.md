## 1. i18n vs l10n vs g11n

| 용어 | 풀네임 | 의미 |
|------|--------|------|
| i18n | internationalization | 앱이 다국어를 지원할 수 있도록 **구조적으로 준비**하는 작업 (텍스트 분리, 날짜·통화 처리 등) |
| l10n | localization | 특정 지역·언어에 맞게 **실제 번역·변환**하는 작업 |
| g11n | globalization | i18n + l10n을 포함한 **전체 글로벌화 프로세스** |

> i18n은 "i"와 "n" 사이에 18글자가 있어서 i18n이라 부른다.

## 2. 번역 키 관리 전략

### Flat vs Nested

```json
// flat — 키가 길어지지만 구조 파악이 쉬움
{
  "home.title": "홈",
  "home.description": "메인 페이지입니다",
  "auth.login.button": "로그인"
}

// nested — 계층 구조로 관리, 네임스페이스 분리에 유리
{
  "home": {
    "title": "홈",
    "description": "메인 페이지입니다"
  },
  "auth": {
    "login": {
      "button": "로그인"
    }
  }
}
```

### Namespace 전략

```
locales/
  ko/
    common.json       # 공통 (버튼, 레이블 등)
    auth.json         # 인증 관련
    dashboard.json    # 대시보드 관련
  en/
    common.json
    auth.json
    dashboard.json
```

페이지/기능 단위로 네임스페이스를 분리하면 lazy loading이 가능하고, 번역가가 담당 파일만 관리할 수 있다.

## 3. i18next + react-i18next

가장 널리 쓰이는 i18n 라이브러리 조합. 프레임워크 비종속적이며 풍부한 플러그인 생태계를 가진다.

### 설치

```bash
npm install i18next react-i18next i18next-browser-languagedetector i18next-http-backend
```

### 기본 설정 (src/i18n.ts)

```ts
import i18n from "i18next";
import { initReactI18next } from "react-i18next";
import LanguageDetector from "i18next-browser-languagedetector";
import HttpBackend from "i18next-http-backend";

i18n
  .use(HttpBackend)           // 번역 파일 HTTP 로딩
  .use(LanguageDetector)      // 브라우저 언어 자동 감지
  .use(initReactI18next)
  .init({
    fallbackLng: "en",        // 번역 없을 때 폴백 언어
    defaultNS: "common",      // 기본 네임스페이스
    backend: {
      loadPath: "/locales/{{lng}}/{{ns}}.json",
    },
    detection: {
      order: ["querystring", "cookie", "localStorage", "navigator"],
      caches: ["localStorage", "cookie"],
    },
    interpolation: {
      escapeValue: false,     // React는 자체 XSS 방어를 하므로 false
    },
  });

export default i18n;
```

### useTranslation 훅

```tsx
import { useTranslation } from "react-i18next";

function LoginPage() {
  // 여러 네임스페이스를 동시에 사용 가능
  const { t, i18n } = useTranslation(["auth", "common"]);

  return (
    <div>
      <h1>{t("auth:login.title")}</h1>
      <button onClick={() => i18n.changeLanguage("en")}>
        {t("common:language.switch")}
      </button>
    </div>
  );
}
```

### 인터폴레이션 (변수 삽입)

```json
// ko/common.json
{
  "greeting": "안녕하세요, {{name}}님!",
  "itemCount": "{{count}}개의 항목"
}
```

```tsx
t("greeting", { name: "홍길동" }); // "안녕하세요, 홍길동님!"
t("itemCount", { count: 5 });      // "5개의 항목"
```

### 복수형 처리

i18next는 `_one`, `_other` 접미사(언어별로 다름)로 복수형을 처리한다.

```json
// en/common.json
{
  "item_one": "{{count}} item",
  "item_other": "{{count}} items"
}
```

```tsx
t("item", { count: 1 }); // "1 item"
t("item", { count: 5 }); // "5 items"
```

### Trans 컴포넌트 — JSX 안에 번역

단순 문자열이 아닌 JSX가 포함된 번역에 사용한다.

```json
{
  "terms": "계속하면 <1>이용약관</1>에 동의하는 것입니다."
}
```

```tsx
import { Trans } from "react-i18next";

<Trans i18nKey="terms">
  계속하면 <a href="/terms">이용약관</a>에 동의하는 것입니다.
</Trans>
```

### 언어 감지 (i18next-browser-languagedetector)

```ts
detection: {
  // 감지 순서: URL 쿼리 → 쿠키 → localStorage → 브라우저 설정
  order: ["querystring", "cookie", "localStorage", "navigator", "htmlTag"],
  lookupQuerystring: "lng",   // ?lng=ko
  lookupCookie: "i18next",
  lookupLocalStorage: "i18nextLng",
  caches: ["localStorage", "cookie"],
}
```

### 번역 파일 Lazy Loading

`i18next-http-backend`를 사용하면 필요한 네임스페이스만 동적으로 로드한다.

```tsx
// 페이지 진입 시 "dashboard" 네임스페이스만 로드
const { t, ready } = useTranslation("dashboard", { useSuspense: false });

if (!ready) return <Spinner />;
```

React Suspense와 함께:

```tsx
// App.tsx
<Suspense fallback={<Loading />}>
  <DashboardPage />
</Suspense>

// DashboardPage.tsx — Suspense가 번역 로딩 완료까지 대기
const { t } = useTranslation("dashboard");
```

## 4. next-intl (Next.js App Router)

Next.js 13+ App Router에 최적화된 i18n 라이브러리. Server Component에서도 번역을 사용할 수 있다.

### 설치 및 설정

```bash
npm install next-intl
```

```
messages/
  ko.json
  en.json
src/
  i18n/
    routing.ts
    request.ts
  middleware.ts
  app/
    [locale]/
      layout.tsx
      page.tsx
```

### routing.ts

```ts
// src/i18n/routing.ts
import { defineRouting } from "next-intl/routing";

export const routing = defineRouting({
  locales: ["ko", "en", "ja"],
  defaultLocale: "ko",
});
```

### middleware.ts

```ts
import createMiddleware from "next-intl/middleware";
import { routing } from "./i18n/routing";

export default createMiddleware(routing);

export const config = {
  matcher: ["/((?!api|_next|.*\\..*).*)"],
};
```

### request.ts

```ts
// src/i18n/request.ts
import { getRequestConfig } from "next-intl/server";
import { routing } from "./routing";

export default getRequestConfig(async ({ requestLocale }) => {
  const locale = await requestLocale ?? routing.defaultLocale;
  return {
    locale,
    messages: (await import(`../../messages/${locale}.json`)).default,
  };
});
```

### useTranslations — Client / Server Component

```tsx
// Server Component (async 함수)
import { getTranslations } from "next-intl/server";

export default async function HomePage() {
  const t = await getTranslations("Home");
  return <h1>{t("title")}</h1>;
}

// Client Component
"use client";
import { useTranslations } from "next-intl";

export function Header() {
  const t = useTranslations("Header");
  return <nav>{t("nav.home")}</nav>;
}
```

### useFormatter — 날짜·숫자 포맷

```tsx
"use client";
import { useFormatter } from "next-intl";

function PriceDisplay({ price, date }: { price: number; date: Date }) {
  const format = useFormatter();

  return (
    <div>
      <span>{format.number(price, { style: "currency", currency: "KRW" })}</span>
      <time>{format.dateTime(date, { dateStyle: "long" })}</time>
      <span>{format.relativeTime(date)}</span>
    </div>
  );
}
```

### URL 기반 로케일 라우팅

```
/ko/about    → 한국어
/en/about    → 영어
/about       → defaultLocale(ko)로 리다이렉트
```

```tsx
import { Link, useRouter, usePathname } from "next-intl";

// locale-aware Link — 자동으로 현재 locale prefix 추가
<Link href="/about">About</Link>

// locale 전환
const router = useRouter();
router.replace(pathname, { locale: "en" });
```

## 5. Lingui.js

React + TypeScript에 최적화된 i18n 라이브러리. 소스 코드에서 번역 문자열을 **자동 추출**하는 것이 강점이다.

### 설치

```bash
npm install @lingui/react @lingui/core
npm install -D @lingui/cli @lingui/babel-plugin-transform-react
```

### lingui.config.ts

```ts
import { defineConfig } from "@lingui/conf";

export default defineConfig({
  sourceLocale: "ko",
  locales: ["ko", "en", "ja"],
  catalogs: [{
    path: "src/locales/{locale}/messages",
    include: ["src"],
  }],
  format: "po",  // PO 파일 형식 (번역가 친화적)
});
```

### 컴포넌트에서 사용

```tsx
import { Trans, useLingui } from "@lingui/react";
import { msg } from "@lingui/core/macro";

function WelcomeMessage({ name }: { name: string }) {
  const { _ } = useLingui();

  return (
    <div>
      {/* Trans 매크로 — JSX 형태 번역 */}
      <Trans>안녕하세요, <strong>{name}</strong>님!</Trans>

      {/* msg 매크로 — 문자열 번역 */}
      <button title={_(msg`닫기`)}>X</button>
    </div>
  );
}
```

### 번역 추출 & 컴파일

```bash
# 소스에서 번역 키 자동 추출
npx lingui extract

# PO 파일을 JS 카탈로그로 컴파일
npx lingui compile
```

추출된 PO 파일을 번역가에게 전달 → 번역 후 컴파일하면 완성된 카탈로그가 생성된다.

## 6. 라이브러리 비교표

| 항목 | i18next + react-i18next | next-intl | Lingui.js |
|------|------------------------|-----------|-----------|
| 번들 크기 | ~33 KB | ~14 KB | ~10 KB |
| 프레임워크 | 프레임워크 무관 | Next.js 특화 | React 특화 |
| Server Component | 별도 설정 필요 | 기본 지원 | 제한적 |
| 번역 추출 자동화 | X (수동) | X (수동) | O (CLI 자동화) |
| 복수형 | 접미사 방식 | ICU Message Format | ICU Message Format |
| TypeScript 타입 안전성 | 플러그인 필요 | 기본 지원 | 기본 지원 |
| 플러그인 생태계 | 매우 풍부 | 보통 | 보통 |
| 학습 곡선 | 보통 | 낮음 | 보통 |

**선택 기준**:
- Next.js App Router 프로젝트 → **next-intl**
- React 프로젝트 + 번역 자동화 중요 → **Lingui.js**
- 프레임워크 무관 or 마이그레이션 필요 → **i18next**

```yaml

name: Sync Translations

  push:
    branches: [main]
    paths: ["src/locales/ko/**"]

jobs:

    runs-on: ubuntu-latest
    steps:
      - uses: crowdin/github-action@v1
        with:
          upload_sources: true
          download_translations: true
          crowdin_branch_name: main
        env:
          CROWDIN_PROJECT_ID: ${{ secrets.CROWDIN_PROJECT_ID }}
          CROWDIN_PERSONAL_TOKEN: ${{ secrets.CROWDIN_TOKEN }}
```

## 8. RTL (우→좌 쓰기) 지원

아랍어(`ar`), 히브리어(`he`), 페르시아어(`fa`) 등은 오른쪽에서 왼쪽으로 읽는다.

### HTML dir 속성

```tsx
// 언어에 따라 html dir 속성 동적 설정
const RTL_LANGS = new Set(["ar", "he", "fa", "ur"]);

function RootLayout({ locale, children }: { locale: string; children: React.ReactNode }) {
  const dir = RTL_LANGS.has(locale) ? "rtl" : "ltr";
  return (
    <html lang={locale} dir={dir}>
      <body>{children}</body>
    </html>
  );
}
```

### CSS Logical Properties 사용

RTL/LTR 모두 대응하는 CSS를 작성할 때는 물리적 방향(left/right) 대신 논리적 속성을 사용한다.

```css
/* 나쁜 예 — RTL에서 반전 필요 */
.card {
  padding-left: 16px;
  margin-right: 8px;
  border-left: 3px solid blue;
}

/* 좋은 예 — LTR/RTL 모두 자동 대응 */
.card {
  padding-inline-start: 16px;  /* LTR: left, RTL: right */
  margin-inline-end: 8px;       /* LTR: right, RTL: left */
  border-inline-start: 3px solid blue;
}
```

### Tailwind CSS RTL 플러그인

```bash
npm install tailwindcss-rtl
```

```jsx
<div className="ms-4 ps-2 border-s">  {/* logical margin/padding/border */}
  content
</div>
```

### 아이콘 미러링

방향성 있는 아이콘(화살표, 재생 버튼 등)은 RTL에서 수평 반전이 필요하다.

```css
[dir="rtl"] .icon-directional {
  transform: scaleX(-1);
}
```

## 9. 면접 포인트

**Q. i18n과 l10n의 차이는 무엇인가?**

i18n(국제화)은 앱이 다양한 언어와 지역을 지원할 수 있도록 코드 구조를 준비하는 작업이다. 하드코딩된 문자열을 키로 분리하고, 날짜·통화·숫자 포맷을 locale에 맞게 처리할 수 있게 설계한다. l10n(지역화)은 그 구조 위에서 실제 번역 텍스트를 제공하고 문화적으로 적합하게 조정하는 작업이다.

**Q. react-i18next에서 Trans 컴포넌트를 사용하는 이유는?**

`t()` 함수는 문자열만 반환하므로 번역 텍스트 안에 `<a>`, `<strong>` 같은 JSX 요소를 포함할 수 없다. `Trans` 컴포넌트는 번역 문자열 안의 태그를 실제 JSX 요소로 렌더링해주므로 링크나 강조 표현이 있는 번역에 사용한다.

**Q. 복수형 처리를 어떻게 하나? 언어마다 다른 이유는?**

영어는 1개(one)와 나머지(other) 두 가지 규칙만 있지만, 아랍어는 0, 1, 2, 3~10, 11~99, 나머지 6가지 규칙을 가진다. 러시아어, 폴란드어도 복잡한 복수형 규칙을 가진다. i18next는 `_one`, `_other` 접미사로, next-intl과 Lingui는 ICU Message Format(`{count, plural, one{...} other{...}}`)으로 처리한다.

**Q. Next.js App Router에서 i18n을 구현하는 방법은?**

middleware에서 locale prefix를 감지해 `[locale]` 동적 세그먼트로 라우팅하고, `next-intl`의 `getRequestConfig`로 서버 요청별로 메시지를 로드한다. Server Component에서는 `getTranslations`, Client Component에서는 `useTranslations`를 사용한다.

**Q. RTL 지원 시 CSS에서 주의할 점은?**

`margin-left`, `padding-right` 같은 물리적 방향 속성 대신 `margin-inline-start`, `padding-inline-end` 같은 CSS Logical Properties를 사용하면 LTR/RTL 모두 자동 대응된다. 또한 방향성 있는 아이콘은 RTL에서 `scaleX(-1)`로 수평 반전해야 의미가 올바르게 전달된다.

**Q. 번역 파일 lazy loading이 중요한 이유는?**

모든 번역을 초기 번들에 포함하면 앱 초기 로딩 속도가 느려진다. 네임스페이스 단위로 분리하여 해당 페이지/기능 진입 시에만 로드하면 초기 번들 크기를 줄이고 성능을 개선할 수 있다. i18next-http-backend나 next-intl의 동적 import를 활용한다.
