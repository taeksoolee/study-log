## 1. CPU 스케줄링 개요

CPU 스케줄링은 **준비 큐(Ready Queue)에 있는 프로세스 중 어떤 프로세스에게 CPU를 할당할지 결정하는 작업**이다.

### 1.1 스케줄링이 필요한 시점

- 프로세스가 Running → Waiting 상태로 전환될 때 (I/O 요청 등)
- 프로세스가 Running → Ready 상태로 전환될 때 (타임 퀀텀 만료 등)
- 프로세스가 Waiting → Ready 상태로 전환될 때 (I/O 완료 등)
- 프로세스가 종료될 때

### 1.2 스케줄링 목표 (성능 지표)

| 지표 | 설명 | 목표 |
|------|------|------|
| CPU 이용률 (CPU Utilization) | CPU가 실제로 사용된 비율 | 최대화 |
| 처리량 (Throughput) | 단위 시간당 완료된 프로세스 수 | 최대화 |
| 총 처리 시간 (Turnaround Time) | 프로세스 제출부터 완료까지의 시간 | 최소화 |
| 대기 시간 (Waiting Time) | 준비 큐에서 대기한 총 시간 | 최소화 |
| 응답 시간 (Response Time) | 요청 후 첫 번째 응답이 올 때까지의 시간 | 최소화 |

```
총 처리 시간 = 완료 시간 - 도착 시간
대기 시간   = 총 처리 시간 - 실행 시간
응답 시간   = 첫 번째 CPU 할당 시간 - 도착 시간
```

## 2. 선점형 vs 비선점형 스케줄링

### 2.1 비선점형 (Non-preemptive) 스케줄링

프로세스가 CPU를 할당받으면 **스스로 CPU를 반환할 때까지** 계속 실행된다.

- 컨텍스트 스위칭 오버헤드가 적다
- 응답 시간 예측이 용이하다
- 단, 짧은 프로세스가 긴 프로세스 뒤에서 대기하는 문제가 생긴다
- 예: FCFS, SJF(비선점), Priority(비선점)

### 2.2 선점형 (Preemptive) 스케줄링

운영체제가 현재 실행 중인 프로세스에서 **강제로 CPU를 빼앗아** 다른 프로세스에 할당할 수 있다.

- 응답 시간이 빠르고 공정성이 높다
- 컨텍스트 스위칭 오버헤드가 발생한다
- 공유 데이터 접근 시 동기화 문제가 생길 수 있다
- 예: SRTF, Round Robin, Priority(선점)

## 3. FCFS (First Come First Served)

### 3.1 개념

**먼저 도착한 프로세스를 먼저 처리**하는 가장 단순한 스케줄링 알고리즘이다.
선입선출(FIFO) 큐로 구현되며, **비선점형**이다.

### 3.2 예시

| 프로세스 | 도착 시간 | 실행 시간 |
|---------|----------|----------|
| P1      | 0        | 24       |
| P2      | 1        | 3        |
| P3      | 2        | 3        |

```
간트 차트:
| P1                    | P2  | P3  |
0                       24   27   30

대기 시간:
  P1: 0
  P2: 24 - 1 = 23
  P3: 27 - 2 = 25

평균 대기 시간: (0 + 23 + 25) / 3 = 16ms
```

### 3.3 호위 효과 (Convoy Effect)

짧은 프로세스들이 긴 프로세스 뒤에서 오랫동안 기다리는 현상이다.
위 예시에서 P2, P3는 각각 3ms만 필요하지만 P1(24ms) 때문에 오래 대기한다.

### 3.4 장단점

- 장점: 구현이 단순하고, 공정하다(순서대로 처리)
- 단점: 호위 효과로 인해 평균 대기 시간이 길어질 수 있다

---

## 4. SJF (Shortest Job First)

### 4.1 개념

**실행 시간이 가장 짧은 프로세스를 먼저 처리**하는 알고리즘이다.
비선점형으로 동작하며, **주어진 프로세스 집합에 대해 최적의 평균 대기 시간**을 보장한다.

### 4.2 예시

| 프로세스 | 도착 시간 | 실행 시간 |
|---------|----------|----------|
| P1      | 0        | 6        |
| P2      | 0        | 8        |
| P3      | 0        | 7        |
| P4      | 0        | 3        |

```
간트 차트 (모두 동시 도착):
| P4  | P1    | P3      | P2        |
0     3      9        16         24

대기 시간:
  P4: 0
  P1: 3
  P3: 9
  P2: 16

평균 대기 시간: (0 + 3 + 9 + 16) / 4 = 7ms
(FCFS 기준 평균 대기: (0+6+14+21)/4 = 10.25ms)
```

### 4.3 기아 현상 (Starvation)

짧은 프로세스가 계속 들어오면 **긴 프로세스는 영원히 실행되지 못할 수 있다**.
이를 해결하기 위해 **에이징(Aging)** 기법을 사용한다.

### 4.4 실행 시간 예측 문제

실제로 프로세스의 실행 시간을 미리 알기 어렵다.
**지수 평균(Exponential Average)**으로 예측한다:

```
τ(n+1) = α × t(n) + (1 - α) × τ(n)

τ(n+1) : 다음 CPU 버스트 예측값
t(n)   : 현재 CPU 버스트 실제값
α      : 가중치 (0 ≤ α ≤ 1, 보통 0.5 사용)
```

## 5. SRTF (Shortest Remaining Time First)

### 5.1 개념

SJF의 **선점형 버전**이다. 새로운 프로세스가 도착할 때마다 현재 실행 중인 프로세스의 **남은 실행 시간**과 비교하여, 더 짧은 프로세스에게 CPU를 넘겨준다.

### 5.2 예시

| 프로세스 | 도착 시간 | 실행 시간 |
|---------|----------|----------|
| P1      | 0        | 8        |
| P2      | 1        | 4        |
| P3      | 2        | 9        |
| P4      | 3        | 5        |

```
간트 차트:
| P1 | P2    | P4      | P1          | P3               |
0    1      5        10            17                26

- t=0: P1 실행 (남은 시간 8)
- t=1: P2 도착 (버스트 4) → P1 남은 7 > P2의 4 이므로 P2 선점
- t=5: P2 완료, P4 도착(버스트 5) → P1 남은 7 > P4의 5 이므로 P4 선점
- t=10: P4 완료 → P1 남은 7 < P3의 9 이므로 P1 계속

대기 시간:
  P1: (10 - 1) = 9    (실행 1ms 후 선점되어 9ms 대기)
  P2: 0
  P3: 15
  P4: 2

평균 대기 시간: (9 + 0 + 15 + 2) / 4 = 6.5ms
```

### 5.3 특징

- 이론적으로 최적의 평균 대기 시간을 보장한다
- 선점 오버헤드와 기아 현상이 발생할 수 있다

## 6. Round Robin (RR)

### 6.1 개념

**시분할 시스템**을 위해 설계된 선점형 스케줄링이다.
각 프로세스는 **타임 퀀텀(Time Quantum, 시간 할당량)** 만큼 CPU를 사용하고, 시간이 지나면 준비 큐의 맨 뒤로 돌아간다.

### 6.2 예시 (타임 퀀텀 = 4ms)

| 프로세스 | 도착 시간 | 실행 시간 |
|---------|----------|----------|
| P1      | 0        | 24       |
| P2      | 0        | 3        |
| P3      | 0        | 3        |

```
간트 차트:
| P1   | P2  | P3  | P1   | P1   | P1   | P1   | P1   |
0      4    7    10    14    18    22    26    30

대기 시간:
  P1: 10 - 4 = 6ms (총 대기: 0→실행, 7→대기, ... 복잡)
  P2: 4
  P3: 7

평균 대기 시간: (6 + 4 + 7) / 3 = 5.67ms
```

### 6.3 타임 퀀텀의 영향

```
타임 퀀텀이 매우 큰 경우:
  → FCFS와 동일하게 동작
  → 응답 시간이 길어진다

타임 퀀텀이 매우 작은 경우:
  → 컨텍스트 스위칭이 너무 자주 발생
  → 오버헤드 증가로 실제 처리 성능 저하

일반적으로 타임 퀀텀은 10~100ms 범위가 적절하다
컨텍스트 스위칭 시간은 타임 퀀텀의 10% 미만이어야 한다
```

### 6.4 특징

- 모든 프로세스가 공평하게 CPU를 사용한다 (공정성)
- 응답 시간이 빠르다 (인터랙티브 시스템에 적합)
- n개의 프로세스, 타임 퀀텀 q일 때 대기 시간은 최대 `(n-1) × q`

## 7. Priority Scheduling

### 7.1 개념

각 프로세스에 **우선순위(Priority)**를 부여하고, 가장 높은 우선순위의 프로세스를 먼저 실행하는 알고리즘이다.
선점형, 비선점형 모두 구현 가능하다.

```
우선순위 결정 기준:
  - 내부: 실행 시간, 메모리 요구량, I/O 비율
  - 외부: 사용료, 부서, 중요도
```

### 7.2 기아 현상 (Starvation)과 에이징 (Aging)

우선순위가 낮은 프로세스가 계속 밀려 실행되지 못하는 **기아 현상**이 발생할 수 있다.

**에이징(Aging)**: 대기 시간이 길어질수록 프로세스의 우선순위를 점진적으로 높여주는 기법.

```
예시: 매 15분마다 대기 중인 프로세스의 우선순위를 1씩 증가
      초기 우선순위 127인 프로세스도 최대 약 32시간 후에는 우선순위 0이 됨
```

### 7.3 예시

| 프로세스 | 도착 시간 | 실행 시간 | 우선순위(낮을수록 높음) |
|---------|----------|----------|-----------------------|
| P1      | 0        | 10       | 3                     |
| P2      | 0        | 1        | 1                     |
| P3      | 0        | 2        | 4                     |
| P4      | 0        | 1        | 5                     |
| P5      | 0        | 5        | 2                     |

```
간트 차트 (비선점):
| P2 | P5     | P1         | P3   | P4 |
0    1       6            16    18   19

평균 대기 시간: (6 + 0 + 16 + 18 + 1) / 5 = 8.2ms
```

## 8. 멀티레벨 큐 (Multilevel Queue)

### 8.1 개념

준비 큐를 **여러 개의 큐로 분리**하고, 각 큐에 서로 다른 스케줄링 알고리즘을 적용하는 방식이다.

```
우선순위 높음
┌─────────────────────────────┐
│   System Processes          │ ← 최고 우선순위
├─────────────────────────────┤
│   Interactive Processes     │ ← Round Robin
├─────────────────────────────┤
│   Interactive Editing       │
├─────────────────────────────┤
│   Batch Processes           │ ← FCFS
├─────────────────────────────┤
│   Student Processes         │ ← 최하 우선순위
└─────────────────────────────┘
우선순위 낮음
```

### 8.2 멀티레벨 피드백 큐 (Multilevel Feedback Queue)

프로세스가 큐 사이를 **이동**할 수 있다.
CPU를 많이 사용하는 프로세스는 낮은 우선순위 큐로 이동하고,
오래 대기한 프로세스는 높은 우선순위 큐로 승격(에이징)된다.

```
Q0 (타임 퀀텀 8ms)  → 완료 못하면 Q1으로 이동
Q1 (타임 퀀텀 16ms) → 완료 못하면 Q2로 이동
Q2 (FCFS)
```

## 9. 알고리즘 비교표

| 알고리즘     | 선점 여부 | 기아 현상 | 특징                          | 적합한 환경       |
|-------------|---------|---------|------------------------------|-----------------|
| FCFS        | 비선점  | 없음    | 구현 단순, 호위 효과            | 배치 시스템       |
| SJF         | 비선점  | 있음    | 최적 평균 대기, 예측 어려움     | 배치 시스템       |
| SRTF        | 선점    | 있음    | 이론적 최적, 오버헤드 높음      | 이론적 기준       |
| Round Robin | 선점    | 없음    | 공정성, 응답성 좋음             | 시분할, 대화형    |
| Priority    | 선점/비 | 있음    | 에이징으로 기아 해결            | 실시간 시스템     |
| MLQ         | 선점    | 있음    | 프로세스 종류별 최적화          | 범용 OS          |
| MLFQ        | 선점    | 없음    | 동적 우선순위, 가장 유연        | 범용 OS (Linux) |

## 10. 면접 포인트

### Q1. FCFS에서 호위 효과(Convoy Effect)란 무엇인가요?

긴 실행 시간을 가진 프로세스가 CPU를 점유하면, 그 뒤에 도착한 짧은 프로세스들이 오랫동안 대기해야 하는 현상입니다. 예를 들어 24ms가 필요한 프로세스 뒤에 3ms 프로세스 2개가 대기하면 평균 대기 시간이 크게 늘어납니다.

### Q2. SJF가 최적임에도 실제로 잘 사용되지 않는 이유는?

프로세스의 다음 CPU 버스트 시간을 정확히 미리 알 수 없기 때문입니다. 실제 시스템에서는 지수 평균 등의 방법으로 예측값을 사용하지만 오차가 발생합니다. 또한 기아 현상이 발생할 수 있습니다.

### Q3. Round Robin에서 타임 퀀텀 크기가 성능에 어떤 영향을 주나요?

- 타임 퀀텀이 크면: FCFS처럼 동작하여 응답 시간이 느려집니다.
- 타임 퀀텀이 작으면: 응답성은 좋아지지만 컨텍스트 스위칭 오버헤드가 증가합니다.
- 최적 타임 퀀텀은 CPU 버스트의 80%가 타임 퀀텀보다 짧도록 설정하는 것이 권장됩니다.

### Q4. 기아 현상(Starvation)이란 무엇이고 어떻게 해결하나요?

우선순위 기반 스케줄링에서 우선순위가 낮은 프로세스가 높은 우선순위의 프로세스들에게 계속 밀려 CPU를 할당받지 못하는 현상입니다. 에이징(Aging) 기법으로 해결합니다. 에이징은 프로세스의 대기 시간이 길어질수록 우선순위를 점진적으로 높여주는 방식입니다.

### Q5. 선점형과 비선점형 스케줄링의 차이점은?

- 비선점형: 프로세스가 CPU를 자발적으로 반환할 때까지 실행. 컨텍스트 스위칭 오버헤드 낮음. 응답 시간이 길 수 있음.
- 선점형: OS가 강제로 CPU 회수 가능. 응답성이 좋고 공정하지만 컨텍스트 스위칭 비용 발생. 공유 자원 동기화가 필요함.

### Q6. 멀티레벨 피드백 큐(MLFQ)가 다른 알고리즘보다 나은 이유는?

MLFQ는 하나의 알고리즘에 고정되지 않고, 프로세스의 동작 패턴에 따라 동적으로 우선순위를 조정합니다. CPU 집약적 프로세스는 낮은 큐로 내려가고, 오래 기다린 프로세스는 높은 큐로 올라가기 때문에 기아 현상을 방지하면서도 I/O 집약적인 인터랙티브 프로세스에게 빠른 응답성을 제공합니다. 대부분의 범용 OS에서 이 방식을 채택합니다.
